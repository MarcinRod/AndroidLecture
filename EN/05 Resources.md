# Application Resources in Android and Compose

## What Are Resources?

**Resources** are all additional files and data used by application outside source code. Examples include: texts, colors, images, sizes. In Android they are stored in `res/` directory.

---

## Types of Resources in Android

Android supports many kinds of resources used by applications:

- **Texts** (`res/values/strings.xml`) – captions, messages, labels, descriptions, error messages, button texts.
- **Colors** (`res/values/colors.xml`) – color definitions used in application.
- **Raster images** (`res/drawable/`) – PNG, JPG, WebP files.
- **Vector images** (`res/drawable/`) – XML VectorDrawable files.
- **Application icons** (`res/mipmap/`) – launcher icons in various resolutions.
- **Dimensions** (`res/values/dimens.xml`) – margins, padding, text sizes, widths, heights. *(In Compose `Dp` values are specified directly in code; `dimens.xml` is rarely used)*
- **Styles** (`res/values/styles.xml`) – style definitions for views (e.g., fonts, colors, margins). *(Rarely used in Compose)*
- **Themes** (`res/values/themes/`) – overall application themes (e.g., light/dark). *(Compose uses its own theming system)*
- **Arrays** (`res/values/arrays.xml`) – lists of texts, colors, numbers.
- **Raw files** (`res/raw/`) – any binary files, e.g., sounds, videos, text files.
- **Fonts** (`res/font/`) – TTF/OTF font files.
- **Animations** (`res/anim/`, `res/animator/`) – XML animations (e.g., transitions, movements). *(Not used in Compose; animations are implemented in code)*
- **Menus** (`res/menu/`) – application menu definitions. *(Not used in Compose)*
- **Layouts** (`res/layout/`) – XML files with view layouts (mainly in classic Android, less in Compose). *(Not used in Compose)*

> **Note:**  
> Resources marked in italics *(...)* are typical for classic Android (View System) and are not used or used marginally in Jetpack Compose. In Compose UI, layouts, animations, and styles are defined directly in Kotlin code.

## Resource ID and `R` Class

Every resource in Android receives a **unique identifier**, automatically generated during compilation and stored in class `R`.

- Class `R` is generated by Android and contains nested classes for resource types, e.g., `R.string`, `R.drawable`, `R.color`, `R.dimen`.
- This allows safe reference to resources in code, e.g.:
  - `R.string.app_name`
  - `R.drawable.ic_launcher`
  - `R.color.primary`
  - `R.dimen.padding_large`

**Usage Example in Compose:**
```kotlin
Text(text = stringResource(id = R.string.greeting))
Image(painter = painterResource(id = R.drawable.avatar), contentDescription = null)
val color = colorResource(id = R.color.my_color)
val padding = dimensionResource(id = R.dimen.padding_large)
```

> **Note:**  
> Resources can also be accessed using context:  
> ```kotlin
> val context = LocalContext.current
> val appName = context.getString(R.string.app_name)
> val drawable = ContextCompat.getDrawable(context, R.drawable.avatar)
> ```

**How Does It Work?**  
During compilation Android assigns each resource a unique ID and generates class `R` allowing easy and safe reference to resources in code – without needing file paths or names as text.

## Storing Text in Resources

All text appearing in application (e.g., titles, descriptions, messages, button texts) should be stored in `res/values/strings.xml` file. This allows:

- easy support for multiple languages (internationalization),
- managing all texts in one place,
- changing text without modifying source code.

**`strings.xml` Example:**
```xml
<resources>
    <string name="app_name">My Application</string>
    <string name="greeting">Hello, user!</string>
    <string name="button_ok">OK</string>
    <string name="error_network">No internet connection</string>
</resources>
```

**In Compose:**
```kotlin
Text(text = stringResource(id = R.string.greeting))
```

---

## Text Formatting with Parameters

Strings in `strings.xml` can contain **placeholders** – places where values are inserted at runtime.

**`strings.xml` Example:**
```xml
<string name="welcome_user">Hello, %1$s!</string>
<string name="item_count">Found %1$d items.</string>
```

- `%1$s` – first text argument
- `%1$d` – first integer argument
- Numbering (`%1$`, `%2$`) allows changing argument order during translation.

**In Compose:**
```kotlin
Text(text = stringResource(R.string.welcome_user, userName))
Text(text = stringResource(R.string.item_count, results.size))
```

---

## Text Pluralization

Android supports plural forms through `<plurals>` element in `strings.xml`. Needed when displayed message depends on count (e.g., "1 result" vs "5 results").

**`strings.xml` Example:**
```xml
<plurals name="search_results">
    <item quantity="one">Found %1$d result.</item>
    <item quantity="few">Found %1$d results.</item>
    <item quantity="many">Found %1$d results.</item>
    <item quantity="other">Found %1$d results.</item>
</plurals>
```

Available categories: `zero`, `one`, `two`, `few`, `many`, `other` – Android chooses appropriate form depending on system language.

**In Compose:**
```kotlin
val context = LocalContext.current
val text = context.resources.getQuantityString(R.plurals.search_results, count, count)
Text(text = text)
```

> Jetpack Compose doesn't have dedicated composable for `plurals` – resources must be accessed through context.

## Images: drawable vs mipmap

- **`drawable/`** – place images used in application (e.g., illustrations, backgrounds, button icons). Supports raster (PNG, JPG) and vector (XML) graphics.
- **`mipmap/`** – directory for application icons only. Android automatically chooses appropriate version based on screen resolution.

**In Compose:**
```kotlin
Image(
    painter = painterResource(id = R.drawable.my_image),
    contentDescription = "Image description"
)
```
Application icon is set in manifest and shouldn't be used in application UI.

## Alternative Resources

Android allows creating **alternative resource versions** for different languages, resolutions, screen orientations, dark/light mode, and other device features. This allows application to automatically adapt to device and user preferences without additional code.

**Examples of alternative directories:**
- `res/values-pl/strings.xml` – Polish texts,
- `res/values-en/strings.xml` – English texts,
- `res/drawable-hdpi/` – images for high-resolution screens,
- `res/values-land/` – resources for landscape orientation,
- `res/values-night/` – colors and styles for dark mode,
- `res/values-sw600dp/` – resources for tablets and large screens.

**How Does It Work?**  
Android automatically chooses appropriate resource based on system settings and device parameters (language, resolution, orientation, dark mode, etc.).  
E.g., if user has Polish language set, system uses `strings.xml` from `values-pl` directory. If device is in dark mode, it fetches colors from `values-night/colors.xml`.

**Advantages of Alternative Resources:**
- Facilitate internationalization (multilingual) of applications.
- Allow optimization of appearance and behavior on different devices (phones, tablets, foldables).
- Enable dark mode support without additional code.
- Allow UI adaptation to screen orientation or display size.

> **Tip:**  
> When creating alternative resources, just add appropriate directory in `res/` folder and place file with same name as in base directory. Android will automatically choose correct file at runtime.

## Colors and Themes in Compose

In applications based on Jetpack Compose, colors are defined in two ways:

| Method | When to Use |
|--------|-------------|
| `MaterialTheme.colorScheme` | Basic UI colors (background, surface, primary color, text). Recommended in Compose. |
| `colorResource(R.color.xxx)` | When specific color from `colors.xml` is needed, e.g., brand color outside Material palette. |

```xml
<!-- res/values/colors.xml -->
<resources>
    <color name="brand_primary">#6200EE</color>
    <color name="brand_secondary">#03DAC5</color>
</resources>
```

```kotlin
// ui/theme/Color.kt
val BrandPrimary = Color(0xFF6200EE)
val BrandSecondary = Color(0xFF03DAC5)
```

Material 3 generates full color palette (light and dark) based on single base color. Therefore in typical Compose application you don't need to manually define many colors – just configure the theme.

**`MaterialTheme` Usage Example in Compose:**
```kotlin
Text(
    text = "Hello",
    color = MaterialTheme.colorScheme.primary
)
Surface(
    color = MaterialTheme.colorScheme.background
) { ... }
```

**`colors.xml` still makes sense** for storing brand colors (hex), which are then passed to theme configuration.

## Shapes in Material 3

Like colors, Material 3 provides system shape set through `MaterialTheme.shapes`. Instead of manually defining `RoundedCornerShape` in every component, use predefined sizes:

| Token | Default Value | Example Usage |
|-------|-----------------|--------------------------|
| `MaterialTheme.shapes.small` | `RoundedCornerShape(4.dp)` | Buttons, text fields |
| `MaterialTheme.shapes.medium` | `RoundedCornerShape(8.dp)` | Cards, dialogs |
| `MaterialTheme.shapes.large` | `RoundedCornerShape(16.dp)` | Bottom sheets, large cards |
| `MaterialTheme.shapes.extraLarge` | `RoundedCornerShape(28.dp)` | Large surfaces |

**Example:**
```kotlin
Card(
    shape = MaterialTheme.shapes.medium
) { ... }

Button(
    shape = MaterialTheme.shapes.small,
    onClick = { }
) { Text("Click") }
```

Shapes can be customized globally in theme configuration – change in one place affects all UI.

## Tips

- **For accessing resources in Compose** use dedicated functions (`stringResource`, `colorResource`, `painterResource`, `dimensionResource`).
- **Don't store `Context` references** outside composable functions – see Activity chapter for more.
- **Store all texts in `strings.xml`** – facilitates translation and content management. For parametrized text use `%1$s` / `%1$d`, for numerals — `<plurals>`.
- **Create alternative resources** for different languages and resolutions to make application universal.

- **Best practice: fetch colors and shapes from `MaterialTheme`** (`colorScheme`, `shapes`) – ensures consistency with application theme and facilitates customization.
- **Use `colors.xml` for storing brand colors (hex)**, which are then passed to theme configuration – don't reference them directly in composable functions.
